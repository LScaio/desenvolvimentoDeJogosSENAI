O Markdown é uma linguagem de marcação leve (lightweight markup) criada por John Gruber (com colaboração de Aaron Swartz) com o objetivo de permitir escrever texto formatado de maneira simples e legível, que depois é convertido em HTML. 
Wikipédia
 Em outras palavras: em vez de usar tags HTML completas, você insere símbolos como #, *, _ etc., para indicar títulos, listas, negrito, itálico, entre outros. 
markdownguide.org

No contexto do GitHub, o Markdown ganhou uma família particular chamada GitHub Flavored Markdown (GFM). Esse dialeto estende o Markdown “padrão” com recursos extras úteis para o ambiente de desenvolvimento colaborativo: listas de tarefas (checkboxes), tabelas, links automáticos, menções a usuários (“@usuario”), entre outros.

Sintaxe essencial e particularidades no GitHub

Aqui estão os elementos mais comuns de formatação que você vai usar no Markdown do GitHub, além de algumas extensões do GFM:

Títulos / cabeçalhos: use #, ##, ### etc., dependendo do nível. Exemplo: ## Seção.

Negrito e itálico:
• Negrito: **texto** ou __texto__
• Itálico: *texto* ou _texto_
• Ambos juntos: ***texto*** para negrito + itálico

Variações e “versões” relacionadas

Como o Markdown tem várias implementações, vale saber algumas distinções:

CommonMark: é um esforço de padronização do Markdown, buscando definir um “núcleo” consistente. Muitas implementações modernas (incluindo as do GitHub) baseiam-se (totalmente ou parcialmente) no CommonMark.

Boas práticas ao usar Markdown no GitHub

Mantenha o README.md bem organizado: explique o projeto, como instalar, como usar, exemplos, contribuição, licença etc.

Use links relativos quando possível para referenciar outros arquivos dentro do repositório (por exemplo, docs/CONTRIBUTING.md) — Dessa forma, eles continuam funcionando ao mudar de branch ou fork. 
GitHub Docs

Não abuse de HTML inline; embora seja permitido em muitos casos, priorize sintaxe Markdown “pura” para manter legibilidade.

Use listas de tarefas para comunicar progresso, pendências ou meta de funcionalidades no projeto.

Teste a visualização no GitHub (pré-visualização) para ver como seu Markdown será renderizado.

Organize seções com títulos e subtítulos para facilitar leitura e gerar sumário automático (GitHub gera um menu de navegação para arquivos grandes).
